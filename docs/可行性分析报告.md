# 《云农智诊——基于 NFNet-F1 与大语言模型的农业智能问诊系统》可行性分析报告

## 1 引言

### 1.1 项目背景

我国基层农技服务存在“人少、面广、响应慢”的结构性矛盾：农户难以及时获得专业病虫害诊断与防治建议，传统人工巡田与电话问诊难以覆盖突发疫情。深度学习在植物病害图像识别领域已趋成熟，大语言模型（LLM）亦具备将结构化识别结果转化为可理解防治建议的能力。在此背景下，建设“识别 + 问诊 + 社区 + 管理”一体化的农业智能问诊平台具有明确的现实需求。

### 1.2 项目目标

《云农智诊》旨在构建一套面向农户、农技员与管理员的多端协同系统：前端采用 Vue3（Web）与微信小程序，后端依托微信云开发（Serverless）完成业务与数据持久化，AI 推理部署于微信云托管（FastAPI + NFNet-F1），智能问诊通过智谱 GLM / DeepSeek API 完成。系统目标包括：（1）实现农作物叶片病虫害的自动化识别；（2）基于识别结果提供自然语言防治建议；（3）支撑农技社区交流与内容审核；（4）提供角色化后台管理能力。

---

## 2 技术可行性

### 2.1 前后端分离架构成熟度

系统采用 **B/S + 前后端分离** 架构：表现层（Vue3 / 小程序）通过 HTTPS 调用云函数与云托管 API，业务逻辑与数据访问下沉至 Serverless 后端。该模式在业界已高度标准化，组件库（如 Element Plus）、鉴权（JWT / 微信登录态）与 RESTful / 云函数调用约定完备，开发风险可控，符合课程设计对“可演示、可部署、可测试”的要求。

### 2.2 NFNet-F1 轻量部署与 OOM 对策

NFNet-F1 属于高精度图像分类骨干，在云托管有限内存环境下存在 **OOM（Out of Memory）** 风险。技术上可通过以下成熟手段规避：

| 策略 | 说明 |
|------|------|
| 推理设备与精度 | CPU / 半精度（如可行）推理，关闭不必要的梯度与缓存 |
| 输入归一化 | 统一 Resize 至固定分辨率（如 512×512），控制显存/内存峰值 |
| 单例加载 | 进程内全局加载一次模型权重，避免每次请求重复加载 |
| 请求串行/限流 | 限制并发推理，防止瞬时堆叠导致内存尖峰 |
| 无状态容器 | 云托管水平扩展，故障实例可快速重建 |

上述方案在 FastAPI + PyTorch/timm 工程实践中已验证可行，模型推理链路与业务库解耦，满足“识别服务可独立运维”的架构约束。

### 2.3 大模型 API 接入成熟度

智谱 GLM / DeepSeek 均提供 OpenAI 兼容或官方 HTTP API。系统仅需将“病害类别、置信度、作物上下文”组装为 Prompt，由云端完成生成，**无需本地部署千亿级参数模型**，显著降低算力与运维门槛。超时（如 60s）、重试与降级提示属于常规接口工程能力，技术风险低。

**结论（技术）**：所选技术栈成熟、可获取文档与社区支持充分，关键路径（图床 URL → 云托管推理 → 业务库落库 → LLM 问诊）清晰，具备实施可行性。

## 3 经济可行性

### 3.1 开发成本

本项目为课程设计，人力成本由课程组承担；软件栈均采用开源或免费配额方案（Vue3、FastAPI、微信开发者工具等），**额外商业授权费用可视为 0 元**。

### 3.2 运维成本

| 成本项 | 说明 | 课设阶段评估 |
|--------|------|----------------|
| 微信云开发 | 免费额度覆盖数据库、云存储、云函数调用 | 低 / 可忽略 |
| 微信云托管 | 按量计费，课设流量下多处于免费或极低成本区间 | 低 |
| 图床（如 ImgBB） | 免费 API Key | 0 |
| 大模型 Token | 厂商新用户/学生免费额度可支撑演示与联调 | 低 / 阶段性 0 |

在课设演示规模下，系统满足 **低成本甚至零边际成本** 运行；若未来商用，再按 DAU 与 Token 消耗做弹性扩容即可，不构成当前实施障碍。

**结论（经济）**：开发与演示运维成本可控，经济上可行。

## 4 操作可行性

### 4.1 农户

Web / 小程序提供“拍照/选图 → 一键识别 → 查看结果 → AI 问诊”的短路径交互，符合非专业用户心智模型；对低置信度结果给出“重新拍照”引导，降低误诊带来的操作挫败感。

### 4.2 农技员

农技员可在社区发布科普帖、解答农户疑问，操作集中在“发帖 / 评论 / 优质标记”等熟悉的内容社区范式，学习成本低。

### 4.3 管理员

管理端提供用户管理、帖子审核、病害库维护等菜单化功能，权限与路由守卫分离，符合后台信息系统操作习惯。

**结论（操作）**：多角色任务边界清晰，界面路径短、反馈明确，具备良好的操作可行性。

---

## 5 社会可行性

项目契合国家智慧农业与数字乡村建设方向，可缓解基层农技力量不足的问题：农户获得即时初诊能力，农技员通过社区实现知识扩散，管理员保障内容与账号安全。系统强调“辅助决策”而非替代专家，符合技术伦理与农技服务规范，社会接受度高。

**结论（社会）**：对智慧农业与基层服务具有正向价值，社会可行性良好。

---

## 6 综合结论

从技术成熟度、经济成本、操作易用性与社会效益四方面综合评估，《云农智诊》系统 **具备实施条件**。建议按“识别闭环优先、问诊与社区并行、管理后台保障内容质量”的迭代顺序推进实现与验收。
