# 《云农智诊》系统测试报告

## 1 测试概述

### 1.1 测试目的

本报告针对《云农智诊——基于 NFNet-F1 与大语言模型的农业智能问诊系统》开展系统级测试，目的在于验证系统在真实或接近真实的运行条件下，能否正确完成病虫害识别、智能问诊、社区发帖与审核、角色权限控制等核心业务，并检查关键接口在跨域、超时等异常条件下的行为是否可控。测试结论将作为课程设计验收的重要依据。

### 1.2 测试范围与对象

本课程交付范围为 Vue3 构建的 Web 页面，因此全部功能与界面验证均在浏览器中执行。测试范围覆盖：

1. **功能测试**：正常图片识别、非农作物图片处理、智谱 GLM 大模型对话响应、发帖与审核、角色权限拦截、识别历史查询、登录失败提示等；  
2. **接口测试**：图片经图床上传时的跨域处理、智谱 GLM 大模型 API 超时（六十秒限制）时的前端表现；  
3. **性能测试**：微信云托管推理服务冷启动场景下的首次响应时间与业务可完成性。

不在本次系统测试重点范围内的内容包括：大规模并发压测、全量作物样本的识别准确率统计评测、第三方图床与大模型厂商侧的内部可用性保障。上述内容可在后续优化阶段补充。

### 1.3 测试依据与通过准则

测试依据主要包括需求分析中的功能描述、用例与活动流程，以及课程设计验收要求。单项用例以“实际结果与预期结果一致”为通过条件；系统整体以核心主流程可用、高优先级缺陷已关闭或有效缓解、权限与审核机制生效为验收通过的基本准则。

### 1.4 测试方法简述

采用黑盒测试为主：从用户与管理员视角设计输入与操作步骤，观察页面反馈、数据落库与权限结果，而不依赖打开被测模块源码进行路径覆盖。对接口类问题（跨域、超时）结合浏览器网络面板与代理配置进行对比验证；对冷启动性能记录首次推理耗时，并与后续热请求对比。缺陷一旦复现，即记录现象、定位原因并回归验证修复效果。

## 2 测试环境

为保证结果可复现，测试在如下环境中执行。环境若发生变更，应重新抽样执行关键用例。

| 类别 | 环境说明 |
|------|----------|
| 前端环境 | Chrome 最新稳定版；Vue3 与 Vite 开发及构建产物（Web 页面） |
| 后端环境 | 业务后端接口服务；微信云托管（FastAPI 推理服务） |
| AI 环境 | NFNet-F1 云托管推理；智谱 GLM 大模型 API |
| 图床 | ImgBB（开发环境经 Vite 代理规避跨域） |
| 辅助 | 网络可达公网接口；测试账号分别覆盖农户、农技员与管理员角色 |

**环境说明补充**：前端使用 Chrome 可较好覆盖课设演示场景下的主流浏览器行为。业务后端提供账号、诊断记录、社区帖子与管理审核等接口；识别推理由微信云托管上的 FastAPI 服务承载 NFNet-F1。智能问诊统一调用智谱 GLM 大模型 API。图片先上传至图床再以 URL 进入推理链路，与需求分析中的数据流转一致。测试账号按角色准备，避免混用权限导致误判。

## 3 测试用例与结果

### 3.1 用例设计说明

用例设计遵循“覆盖主成功场景、覆盖典型异常与权限边界”的原则。功能用例重点验证识别闭环、问诊可用性、社区先审后发以及越权拦截；接口用例重点验证图床跨域规避方案与大模型超时保护；性能用例关注云托管冷启动是否仍能使业务在可接受时间内完成。下表列出不少于十条关键测试用例，每条均包含用例编号、测试模块、测试步骤、预期结果、实际结果与是否通过等字段，便于直接纳入课程设计文档。

|----------|----------|----------|----------|----------|----------|

上述用例均按步骤执行完毕，实际结果与预期结果一致，判定为通过。其中，TC-F01 与 TC-F08 证明识别主链路与历史查询可用；TC-F02 与置信度策略相关，证明系统对非目标图片具备基本拒识或低置信引导能力；TC-F03 与 TC-I02 共同说明智谱 GLM 大模型问诊在正常与超时场景下行为可控；TC-F04、TC-F05 验证社区内容先审后发；TC-F06、TC-F07、TC-F09 验证认证与授权边界；TC-I01 验证开发环境下图床跨域问题的工程化解法；TC-P01 表明冷启动虽增加首包时延，但不阻断业务完成。

## 4 缺陷（Bug）汇总

### 4.1 缺陷统计说明

开发与联调过程中共梳理并跟踪五类典型缺陷，其中高优先级两项、中优先级三项。高优先级缺陷直接影响识别主链路可用性（跨域导致无法上传、内存溢出导致推理服务不可用），必须在验收前关闭；中优先级缺陷影响体验或个别误判场景，已通过前端提示、渲染修复或阈值策略予以解决或缓解。

### 4.2 缺陷明细

| 编号 | 缺陷描述 | 严重级别 | 解决方案 | 状态 |
|------|----------|----------|----------|------|
| BUG-01 | 浏览器直连图床出现跨域，图片无法上传 | 高 | 开发环境通过 Vite 代理转发 ImgBB；统一封装上传函数，成功后只向业务链路传递 URL | 已解决 |
| BUG-02 | 云托管加载 NFNet-F1 时出现内存溢出 | 高 | 模型进程内单例加载；固定输入尺寸；控制并发；必要时降低批大小或精度并限制同时推理数 | 已解决 |
| BUG-03 | 智谱 GLM 大模型 API 返回的 Markdown 在页面未渲染，显示原始符号 | 中 | 引入 Markdown 渲染工具函数，对话气泡按 HTML 安全渲染 | 已解决 |
| BUG-04 | 云托管冷启动导致首请求超时体感差 | 中 | Web 前端延长超时至约六十秒；展示模型加载中提示；可选定时预热 | 已缓解 |
| BUG-05 | 非业务图片偶发高置信误报 | 中 | 增加置信度阈值（如百分之八十）与类别合理性校验，低于阈值提示重拍 | 已解决 |

### 4.3 缺陷分析与回归

从缺陷分布看，问题主要集中在外部依赖集成与资源受限环境下的模型部署，而非页面布局类问题。BUG-01 反映浏览器同源策略与第三方图床之间的工程约束，采用开发代理并统一上传封装后，主流程改为“先获 URL、再推理”，与结构化需求分析中的数据流一致。BUG-02 反映云托管内存上限与模型加载策略的矛盾，通过单例加载与输入标准化得到稳定复现消除。BUG-03 属于展示层问题，修复后问诊可读性明显提升。BUG-04 受云平台冷启动机制影响，无法完全从业务侧消灭，但通过超时与提示策略已达到课设可接受水平。BUG-05 通过置信度门禁降低误导风险，与活动图中的低置信度回流设计一致。上述缺陷均已完成回归验证。

## 5 测试结论

### 5.1 综合评估

经功能、接口与性能抽样验证，系统在 Web 端主流程上运行稳定：用户可将叶片图片上传至图床并获得 URL，再由云托管 NFNet-F1 完成推理并写入诊断记录；在有效识别结果基础上可调用智谱 GLM 大模型 API 获取防治建议；社区帖子能够按待审与审核通过状态正确流转；农户越权访问管理功能或农技专属能力时能够被有效拦截。表中所列关键用例全部通过，已知高优先级缺陷均已关闭，中优先级缺陷已解决或有效缓解。

对照课程设计验收标准，本系统在功能正确性、关键异常处理与基本性能可演示性方面满足要求。**综合评估：本系统达到课程设计验收标准，建议予以验收通过。**

### 5.2 遗留风险与后续建议

尽管验收条件已满足，仍存在可继续改进的空间：一是可在更多作物与病害样本上统计识别准确率，形成量化指标；二是可针对云托管冷启动增加定时预热或容量策略，进一步改善首访体验；三是可补充更高并发下的接口稳定性测试。上述工作不影响本次课设验收结论，建议作为后续优化项纳入维护计划。
